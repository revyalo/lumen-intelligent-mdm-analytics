# Analytical methodology

## EDA and missingness

Numeric summaries exclude missing/non-finite values, use sample variance/standard deviation (ddof=1), and pandas interpolated quantiles. The first sorted mode is shown if tied. Pearson correlations require at least three paired observations; they do not establish causality. Categorical frequencies show at most 30 values (dashboard labels this cap). Histograms, boxplots, categorical bars, date counts and scatterplots depend on actual field types. Complete missingness patterns and percentages by source make the denominator visible.

IQR flags observations outside Q1−1.5×IQR / Q3+1.5×IQR. Z-score uses the sample mean/SD with |z|>3; skew, small samples and heavy tails limit its usefulness. Constant columns produce no z-score. Missing and infinite values are explicitly ineligible. Flags are observations to investigate, never automatic deletions. The generated bulk purchases are legitimate extremes.

Imputation is opt-in: median for a numeric measurement, mode for a non-identifier attribute. A rationale is mandatory and every changed cell is logged. Fully empty columns cannot be imputed. Missing tax/customer keys, emails and phones are not invented. Univariate imputation can distort group distributions and uncertainty; use source-owner validation for business-critical missingness.

## Quality score

All dimension scores range 0–100. Completeness is nonmissing cells / all cells (blank strings count as missing). Uniqueness is distinct known natural keys / known key observations; source duplicates reduce it even when every record_id is unique. Validity pools applicable email/phone/domain tests. Consistency pools natural-key/name agreement, price/cost relationships and line arithmetic rules. Referential integrity tests required foreign keys against supplied tables. Freshness measures nonfuture updates within 365 days of the explicit reference date. It is not applied to historical transaction dates.

Each rule's denominator is its eligible row count. Rule scores within a dimension are weighted by eligible checks; some rows can participate in several rules. Aggregate = sum(weight×applicable score)/sum(applicable weights). Defaults: completeness .25, uniqueness .20, validity .20, consistency .15, integrity .10, freshness .10. Nonapplicable dimensions are null and excluded. The dashboard offers editable weights. Scores are diagnostic, not certification. A typographical name difference can trigger consistency; a syntax-valid email can still be wrong. Normalization can reduce completeness by quarantining invalid email addresses while increasing validity. Scores need not improve uniformly.

## Business definitions and SQL

Revenue = sum invoices for fulfilled orders, excluding tax. Cancelled orders have no sales. Average ticket = revenue / fulfilled orders, not order lines. Active = at least one fulfilled purchase in the 180-day inclusive window ending at the bundle reference date; inactive includes never-purchasers. Date/region controls restrict the transaction population, so activity is activity observed in that scope. All customers in the selected regions remain in the denominator. Inventory is the full as-of snapshot and is independent of date/region filters. Acquisition uses master created_at, not first observed order.

Monthly sales include zero-sales calendar months between selected order bounds. MoM is undefined after a zero month or without a prior month. Category gross margin uses simulated historical line costs, and excludes operating costs. Weighted price history is affected by product mix; it is not a constant-basket price index. Low rotation uses the bottom quartile of fulfilled units in the selected scope. Top-20% concentration uses ceil(0.2×all customers), including nonbuyers. Temporal comparisons use actual periods and label incomplete quarters.

RFM uses the final 365 days (inclusive) through as_of, intersected with the selected scope. Recency = integer days since last fulfilled purchase, frequency = distinct fulfilled orders, monetary = sum line net amounts. R scores: ≤30/≤90/≤180/>180 days give 4/3/2/1. F scores: ≥6/≥3/≥2/1 give 4/3/2/1. M uses purchasing-customer quartiles with ties sharing scores. Segments, evaluated in order: No purchases; At risk (>180 days); Champions (≤90 days, ≥3 orders, spend ≥buyer median); Loyal (≥3 orders); New (one order, ≤90 days); Occasional. Nonbuyers do not enter K-Means.

## Entity resolution and review

Normalization is deterministic. Candidate blocks use nonmissing tax/email/SKU values, exact normalized names and shared name tokens whose frequency is between 2 and the explicit block cap. Common token blocks are excluded with a reported count; oversized identifier/name blocks and pair budgets fail visibly. Token blocking can miss aliases with no shared tokens; evaluation recall counts every labelled positive pair, including those not generated. Exact matching uses equal natural/contact keys or normalized names. Fuzzy matching uses RapidFuzz WRatio on normalized names. Scores are max(98 for shared key, 95 for exact name, 0.90×name similarity). Scores are ordinal heuristics, never calibrated probabilities. High ≥95; review ≥80; weak <80. A disagreement between known tax/SKU/email values marks a conflict and excludes the pair from automatic experimental predictions.

There are no automatic merges. A reviewer supplies a name and reason; contradictory identity keys need an explicit override. The ledger fingerprints dataset content and keeps all accept/reject/revoke events. Latest decision per pair defines the current graph. Transitive key conflicts block affected unions unless the event explicitly authorizes the conflict. Golden-record values use source priority (administration/catalogue, sales, purchasing, other), then latest update and record ID. Each value retains its source record ID and distinct-value count. Golden IDs derive from member IDs and change if membership changes. Snapshots are regenerated after revocation; original rows are untouched. SQLite is suitable for a trusted local analyst, not an authenticated enterprise workflow. Review reasons may contain user-supplied sensitive information; keep runtime files private.

## ML and evaluation limits

K-Means uses log1p(R,F,M), StandardScaler and 10 seeded initializations. Candidate k=2…min(6,n−1,distinct−1) is selected by maximum in-sample silhouette (deterministic sample of up to 2,000). Cluster profiles use original units; the RFM cross-tab and adjusted Rand index describe agreement with rules, not accuracy. No label enters the model. Cluster numbers have no business ordering.

Isolation Forest uses 120 trees, fixed random seed, original numeric measurements and configurable contamination (default 3%). Incomplete/nonfinite rows are excluded with eligibility flags. Anomaly score = −score_samples; higher is more unusual. Contamination is a model setting, not an estimate of fraud or data error. Precision/recall against injected bulk-purchase labels evaluate detection of a synthetic constructed pattern, not error/fraud detection.

The optional semantic adapter uses an existing local sentence-transformers folder with local_files_only and no remote code. It compares name embedding cosine×100 on at most 1,000 records. It is not required for any core workflow. When no local model exists, results are marked NOT RUN. No fabricated embedding metrics are reported. Exact/fuzzy thresholds are predeclared at 80/85/95 across seeds 42/123. These are descriptive synthetic benchmarks, not a held-out real-world estimate. Identifier-rich numbered names make the base synthetic matching problem easier than typical business data; a separate hand-labelled challenge case tests name-only ambiguity and candidate misses.

The two generated years contain constructed seasonality. We show monthly patterns, but omit forecasting because synthetic performance would not demonstrate operational predictive value. Production rollout would require representative labels, out-of-time evaluation, workload profiling, access controls and domain stewardship.
